## Kết luận

Khi giữ nguyên typed plans, full OCR asset và lexical index, tăng
`top_k_tables_per_operand_year` từ 10 lên 20 đã mở rộng navigation coverage
theo một tín hiệu có thể tái lập:

- candidate-table rows: `10.650 -> 21.280` (`+10.630`);
- physical candidate UIDs duy nhất: `9.707 -> 18.388` (`+8.681`);
- 1.065/1.065 route groups giữ nguyên đúng prefix top-10, nên candidate arm
  chỉ thêm tail rank 11--20 và không đổi thứ tự top-10;
- trên 1.595 source UIDs lấy từ evidence của q82 (đây là reference
  candidate-derived, không phải gold relevant-table labels), UID được tìm thấy
  tăng `667 -> 711` ở ngưỡng K tương ứng (`+44`);
- câu có ít nhất một target UID tăng `514 -> 540` (`+26`);
- câu có đủ toàn bộ target UIDs tăng `490 -> 526` (`+36`);
- không có target UID nào bị mất trong arm top-20.

Đây là cải thiện của score con `retrieval/source-closure`, không phải cải thiện
answer score. Evidence dùng để đo được sinh từ một submission best-effort và
không có official scorer/gold relevant-table labels trong snapshot này. Vì vậy
`ANSWER_ACCURACY` và `EXECUTION_ACCURACY` phải giữ `NOT_MEASURED`; không tích
hợp top-20 trực tiếp vào submission.

## Hypothesis/family

Failure class ở mức population là route có source table đúng nhưng lexical
navigation shortlist top-10 cắt mất table ở rank 11--20 trước khi exact
row/column binding chạy. Quy tắc được thử là:

```text
same ticker + report year + scope policy + metric query
    -> lexical top-20
    -> preserve top-10 order
    -> expose only the tail as additional navigation candidates
    -> hydrate exact source coordinates
    -> Decimal replay / semantic / policy gates
```

Đây là rule theo route/operand/query pattern. `question_id` chỉ được dùng làm
tracking key trong audit, không điều khiển retrieval, ranking, parsing,
formula hay answer selection.

## Diagnostic-only decision

The result is strong enough to keep the top-20 retrieval artifact for the next
experiment, but not to merge it into the answer pipeline. The current
retrieval review packet has `row_index` and value-blind row metadata but leaves
`column_index` unresolved. The primary builder's research-fusion interface
requires concrete hydrated coordinates, and the answer authority still needs
current structured-table hydration, semantic checks, Decimal replay and source
line closure.

The next generalized implementation slice is therefore a **tail-coordinate
materializer**:

1. take all rank 11--20 rows for every eligible route, not a QID allow-list;
2. resolve a column only from the question/operand period, scope and unit
   contract plus value-independent header semantics;
3. emit coordinate hints without emitting numeric values;
4. hydrate those hints from the pinned 146,246-table asset;
5. run the same source/replay/policy gates in a current q82-based control vs
   candidate A/B;
6. report answer/execution accuracy only after the exact official scorer or a
   separately frozen gold set is available.

Do not use retrieval rank, source UID presence, answer diff, replay success or
candidate coverage as a correctness label.
