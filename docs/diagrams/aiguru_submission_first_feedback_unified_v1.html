AI GURU / SUBMISSION-FIRST UNIFIED ARCHITECTURE V1

Submission là đường chính. E2E là feedback loop — và chỉ là gate khi chọn strict release.

Một workflow duy nhất đi từ data/question đến submission. RAG và fine-tune giúp tìm candidate, xếp hạng và tạo proposal; Context Compiler bảo toàn câu hỏi/nhãn nguồn tiếng Việt nhưng có thể dùng system instruction tiếng Anh theo model. E2E quan sát proposal/submission, tạo receipt và failure signal cho phiên bản kế tiếp; nó không tự sửa đáp án của run hiện tại.

SUBMISSION = PRIMARY OUTPUT CONTEXT = VI SOURCE + CANONICAL JSON MODEL OPS = EN INSTRUCTION WHEN MEASURED E2E = FEEDBACK / OPTIONAL STRICT GATE

ONE FLOW / TWO TIME SCALES

Luồng hợp nhất từ data/question đến submission và vòng cải thiện

Đường ngang phía trên là run tạo submission. Rail phía dưới chạy sau đó để đo lỗi, lập experiment, train/re-index hoặc đề xuất code patch, rồi đưa một version đã qua held-out gate về run tiếp theo. Dòng solid là handoff chính; dòng dashed là feedback hoặc next-version route.

PRIMARY PRODUCT PATH

Submission first

Builder tạo candidate ledger, hydrate/replay từ V2 và phát JSON/CSV/ZIP. E2E quan sát cùng proposal và sinh receipt cho feedback.

LANGUAGE POLICY

Không dịch mù toàn bộ context

Giữ câu hỏi và nhãn bảng tiếng Việt làm evidence surface. Dùng canonical JSON keys, controlled aliases và English system instruction chỉ khi A/B chứng minh tốt hơn.

IMPROVEMENT CONTROL

Feedback không tự promote

E2E failure → taxonomy → experiment → train/re-index/code patch → held-out evaluation → human decision. Kaggle chỉ là compute worker.

MODULE CONTRACTS

Một orchestrator mỏng, các module một mục đích

Mục tiêu refactor là để một file orchestration chỉ nối contract, không chứa đồng thời retrieval, prompt construction, scoring, arithmetic và packaging. Tên dưới đây là target boundary; script hiện tại có thể giữ làm compatibility wrapper trong giai đoạn chuyển đổi.

LANGUAGE / MODEL POLICY

Tiếng Việt ở content plane, tiếng Anh có điều kiện ở instruction plane

Đây là chính sách đề xuất, không phải giả định rằng mọi model đều hiểu như nhau. Cùng một model có thể được dùng cho nhiều role, nhưng mỗi role phải có prompt profile, schema, temperature, artifact và metric riêng.

PRESERVE MEANING

Giữ nguyên tiếng Việt ở nơi chứa semantics

  • Question: giữ nguyên câu hỏi tiếng Việt và bản normalized có provenance.
  • Source labels: giữ nhãn dòng/cột, đơn vị và header tiếng Việt; không dịch rồi bỏ bản gốc.
  • RAG query: truy vấn tiếng Việt là chính; thêm ticker, năm, controlled alias tiếng Anh nếu có ích.
  • Canonical fields: output dùng JSON keys ổn định như entity, period_roles, operation, operands.

MODEL-SPECIFIC INSTRUCTION

Dùng English system prompt khi A/B chứng minh lợi ích

  • Planner/generator: instruction tiếng Anh được phép, nhưng input vẫn chứa raw Vietnamese và source labels.
  • Critic/evaluator: English instruction + machine-readable receipt/failure trace; critic không cấp answer authority.
  • Codegen: English instruction + repository API/contracts; output chỉ là patch/test proposal trong sandbox.
  • Không chuyển ngữ identity: hash, UID, row/column index và raw labels phải giữ nguyên.
